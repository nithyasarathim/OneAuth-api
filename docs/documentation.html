Service Overview

OneAuth API is the backend authority behind the OneAuth SSO platform. It is responsible for proving identity, issuing sessions, validating trusted client applications, and returning signed access tokens that downstream products can trust.

The service coordinates:

  • MongoDB for durable user account records.
  • Redis for session tokens, OTPs, verification tokens, and authorization codes.
  • HTTP-only cookies for browser sessions.
  • JWT access tokens for SSO clients.
  • ImageKit CDN storage for profile avatars.
  • OneMail integration for OTP email delivery.

SSO Handshake

The handshake follows an authorization-code pattern:

Client App
→
OneAuth Portal
→
Session Check
→
Validate client_id
→
Auth Code (Redis)
→
JWT Issued
  1. The product application sends the user to OneAuth.
  2. OneAuth validates the user's active session.
  3. If no session exists, the user completes login or signup before authorization continues.
  4. OneAuth validates the requesting client and redirect URL.
  5. A short-lived authorization code is stored in Redis.
  6. The product backend exchanges the code and client secret for a signed JWT.
  7. The product uses the JWT to request user identity through /sso/userinfo.

Security & Middleware

The API uses a layered request pipeline. Some middleware is global, and some is applied per route so each endpoint can have a limit and authentication policy appropriate to its risk.

Incoming Request
↓
requestLogger
Logs method, status, duration, IP, path
↓
rateLimiter
Per-IP, per-route using window size env
↓
authenticator
Reads session_token, attaches req.userId
↓
sessionValidator
Confirms token in Redis (lightweight)
↓
Controller
↓
errorHandler
Converts domain errors → API responses

Persistence model

Data Store Reason
User account and profile MongoDB Durable identity record.
Session token Redis Fast lookup and TTL-based expiry.
Registration OTP Redis Short-lived verification secret.
Verified email token Redis + HTTP-only cookie Bridges OTP verification into account creation.
SSO authorization code Redis One-time, short-lived code for token exchange.
Avatar files ImageKit CDN-backed profile image storage.

Setup

Prerequisites

  • Node.js 20 or newer.
  • MongoDB running locally or through a hosted provider.
  • Redis running locally or through a hosted provider.
  • OneMail (first-party email microservice) reachable through ONE_MAIL_SERVER_URL.
  • ImageKit account credentials for avatar storage.

Install dependencies

npm install

Configure environment

Create a .env file in the API project root and fill all variables listed in the Master Environment & Metrics table.

Start the server

The current package.json does not define a startup script. Use one of the following approaches.

Run the TypeScript entry point with a TS runtime:

npx tsx server.ts

Or add scripts similar to:

{
  "scripts": {
    "dev": "tsx watch server.ts",
    "start": "tsx server.ts"
  }
}

Then start development mode:

npm run dev

The server logs a successful startup as:

One Auth Server is running on http://localhost:8000

Operational Notes

  • CORS is restricted to ONE_AUTH_CLIENT_DOMAIN_URL and enables credentials.
  • Session cookies are HTTP-only and backed by Redis.
  • OTPs, verified tokens, and SSO authorization codes are short-lived Redis records.
  • SSO redirect URIs are exact-match allowlisted.
  • Client secrets are loaded into a Map from ONE_AUTH_CLIENT_ID_SECRET.
  • The service intentionally fails startup when required environment variables are missing.

Recommended Production Hardening

  • Use HTTPS so secure cookies behave correctly in production.
  • Store secrets in a managed secret vault, not in committed files.
  • Rotate ONE_AUTH_JWT_SECRET, client secrets, and mail HMAC secrets on a defined schedule.
  • Use separate Redis databases or key prefixes for staging and production.
  • Keep redirect allowlists narrow and exact.
  • Add centralized log aggregation around requestLogger output.
  • Pin production CORS to the deployed OneAuth Client origin.
